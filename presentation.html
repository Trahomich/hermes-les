Откуда мы начали

Пару месяцев назад я рассказывал вам про OpenClaw — современный подход к работе с ИИ.

Программисты уже вовсю используют Claude в режиме агента, запущенного прямо на рабочей машине.

По сути, это claw-агент на вашем ноутбуке — удобно, но не без проблем.

Почему предыдущие решения не подошли

AnythingLLM — эксперимент оказался неудачным. Платформа заточена под другое, а про безопасность там говорить не о чём.

Все claw-агенты работают через мессенджеры.

Мессенджер — это как минимум дыра в безопасности.

Что удалось сделать

Я соединил Hermes и Open WebUI.

Интерфейс вам знаком — вы уже пару лет пользуетесь им для доступа к ИИ.

Но теперь за привычным веб-интерфейсом стоит не просто модель, а полноценный помощник, который может действовать своими цифровыми руками.

Что такое Hermes Agent

Open-source AI-агентный фреймворк от Nous Research.

Та же категория, что Claude Code, Codex, OpenClaw — автономные агенты с tool calling.

Работает с любыми LLM-провайдерами: OpenRouter, Anthropic, OpenAI, DeepSeek, локальные модели.

Ключевые особенности

Навыки (skills) — Hermes учится на опыте. Сохраняет повторяющиеся процедуры как навыки, переиспользует в будущих сессиях.

Память между сессиями — помнит предпочтения, детали окружения, уроки прошлых разговоров.

Расширяемость — плагины, MCP-серверы, кастомные инструменты, webhook-триггеры, cron, полный доступ к Python-экосистеме.

Как это выглядит на практике

Много сложных слов, но на самом деле всё это происходит под капотом.

Пользователь общается с агентом исключительно текстом — обычный чат, как с коллегой.

Разница в том, что собеседник не просто отвечает, а действует.

Примеры задач

Подключить MCP-сервер и начать с ним работать

Провести исследование по теме

Разработать Helm-чарт и развернуть в Kubernetes

Помочь аналитику разобраться с данными

Провести экспертную оценку по ИБ

И это только начало: задачи по расписанию, работа с документами, отправка в мессенджеры и почту, монотонная рутина с API.

Навыки — один раз объяснил, всегда работает

Заведите чат → добейтесь результата → попросите сохранить в навык → переиспользуйте в любое время

Не нужно каждый раз объяснять заново.

Мультиагентность — как отдел

Вы — руководитель отдела. У вас задача, которую одному не потянуть.

Вы собираете команду: один силён в анализе, другой быстро пишет код, третий проверяет безопасность.

Вы раздаёте задачи, координируете, собираете результат.

Hermes работает так же: вместо одного агента — отдел подчинённых, каждый со своей специализацией.

Мультиагентность в Hermes


Пользователь
    │
    ▼
┌─────────┐
│ Hermes  │ ← основной агент
└────┬────┘
     │
     ├─ delegate_task ──→ [Субагент 1] → результат
     ├─ delegate_task ──→ [Субагент 2] → результат
     └─ delegate_task ──→ [Субагент 3] → результат

До 3 параллельных задач. Родитель получает только финальный summary.

Kanban-оркестрация

Для долговременных проектов — не одна сессия, а постоянная доска.


┌──────────────────────────────────┐
│       Kanban Board (SQLite)      │
│  Backlog → In Progress → Done   │
└────┬──────────┬──────────┬───────┘
     │          │          │
  Worker A   Worker B   Worker C

Диспетчер декомпозирует → воркеры выполняют → результат доставляется

Опасность полного доверия

Доверить агенту полный контроль — как дать ключи от квартиры незнакомцу, который убедительно говорит, что умеет убираться.

Агент может удалить критичные файлы, «помогая» выполнить задачу.

Агент может придумать несуществующую команду — и система сломается.

rm -rf /tmp/ * вместо rm -rf /tmp/* — один пробел, и прощай файловая система.

Ещё риски

Утечка данных: API-ключи, токены, пароли — могут случайно уйти в лог или мессенджер.

Компрометация цепочки: один галлюцинирующий субагент передаёт неверные данные — все следующие агенты работают на основе ложных предпосылок.

Саморасширение привилегий: cron-задача, новый пакет, открытый порт — всё «для задачи», но без контроля человека.

Кнопки «Undo» нет. Git спасает частично.

Решение: Надзиратель (Supervisor)

Ключевая идея: не доверять агенту выполнять команды без предварительной проверки.

Проверка результата ПОСЛЕ выполнения бессмысленна — система уже сломана.

Надзиратель перехватывает и одобряет команды ДО их выполнения.

Схема работы


Пользователь
    │
    ▼
┌──────────────┐
│  Надзиратель  │ ← ограниченный toolset
└──────┬───────┘
       │ делегирует задачу
       ▼
┌──────────────┐
│  Исполнитель │ ← полный toolset
└──────┬───────┘
       │ формирует команды, НЕ выполняет
       ▼
┌──────────────┐
│  Надзиратель  │ ← проверяет ДО выполнения
└──────┬───────┘    опасные — блокирует
       │            безопасные — одобряет
       ▼
  Одобренные → Исполнитель выполняет
       │
       ▼
  Результат → Пользователю

Реализация в Hermes

approvals.mode: smart — встроенная защита из коробки. LLM оценивает каждую shell-команду ДО выполнения: опасные блокирует, безопасные одобряет.

Двухагентная схема через delegate_task:

Ревьюер запускается с пустым toolset — у него нет терминала, файловой системы, браузера. Только анализ текста. Он физически не может выполнить команду, только оценить.

Вердикт: ALLOW / WARN / DENY

Реализовано в навыке command-safety-gate

Ограничения

Надзиратель — тоже LLM. Может галлюцинировать или пропустить угрозу.

Двойная стоимость токенов — два агента вместо одного.

Задержка — проверка плана добавляет время к каждой задаче.

Ложные срабатывания — может заблокировать корректное действие.

Но это дополнительный слой защиты, а не замена человеческому контролю.
